After the [copy from Nexus](/move-from-nexus/), each project still names Nexus. A coding agent, such as Claude Code, can move a project with you.

The agent changes the files. It asks you for the few steps that need a person.

To make the changes yourself, see [Move your projects by hand](/move-projects-by-hand/).

## Choose the prompt

<Choice questions={[

<Steps>

1. Copy the prompt below.

2. Fill in its first lines: your two server addresses, and the name of each repository in Nexus and in Telesphorepo. The **Repositories** page lists the names. A lock after a name means it is private.

3. Open the agent in the project folder, and paste the prompt.

4. Read the changes before you commit them.

</Steps>

<Path title="Gradle or Maven: download addresses only" ecosystem="gradle" scope="downloads">

```text title="Prompt: Gradle or Maven, download addresses only"
Move this project from our Nexus server to Telesphorepo with me. Do every step you can. For
each step marked ME, tell me exactly what to do, then wait until I say it is done. Never put a
password or a token in a file, a command line or this chat: read each secret from an
environment variable or a CI secret. Ask me before you change a file outside the project. Keep
every checksum and hash: Telesphorepo holds the same bytes as Nexus.

Telesphorepo: https://repo.example.com
Nexus: https://nexus.example.com
Repositories (Nexus name -> Telesphorepo name):
- maven-public -> maven-public
- maven-releases -> maven-releases
Private repositories (they need a read token): none

Scope: the download addresses only. Publishing stays on Nexus: leave the publish addresses,
credentials and steps as they are.

Do this:
1. Find every place that names Nexus. Search every file, hidden folders too, for the Nexus
   host and for /repository/. Look in pom.xml, .mvn/maven.config, every settings.xml,
   build.gradle(.kts), settings.gradle(.kts) (pluginManagement,
   dependencyResolutionManagement), gradle.properties, gradle/*.gradle(.kts), buildSrc/,
   build-logic/, init scripts and gradle/wrapper/gradle-wrapper.properties, and in CI files
   (.github/workflows, Jenkinsfile, .gitlab-ci.yml and others), Dockerfiles, compose files,
   scripts and READMEs. Also show me what ~/.m2/settings.xml, ~/.gradle/gradle.properties and
   ~/.gradle/init.d/ on this computer name. For each Nexus repository not in my list, ask me
   its name and wait.
2. Change every download address.
   https://nexus.example.com/repository/<nexus name>/ becomes
   https://repo.example.com/maven/<telesphorepo name>. Only the prefix changes; the files keep
   their paths. A <mirror> with <mirrorOf>*</mirrorOf> points at a Telesphorepo group. A
   distributionUrl on a Nexus raw repository becomes https://repo.example.com/raw/<name>/<path>;
   keep distributionSha256Sum.
3. Lockfiles: Gradle lockfiles and gradle/verification-metadata.xml hold no addresses. Keep
   them.
4. Private repositories, only if my list names one. ME: I make a read token (Settings › Tokens,
   New read token, Create token) and set it, with my username, in
   ORG_GRADLE_PROJECT_<name>Username and ORG_GRADLE_PROJECT_<name>Password for Gradle, and
   TELESPHOREPO_READ_USER and TELESPHOREPO_READ_TOKEN for Maven, here and as CI secrets. Tell
   me these names first, and never ask me for the token. Never use the name
   TELESPHOREPO_TOKEN: the CLI sets it when it publishes. Wire the variables in. Gradle: in the
   maven { } block, name = "<name>" and credentials(PasswordCredentials::class) (Groovy:
   credentials(PasswordCredentials)); <name> is the repository name as a Gradle identifier
   (my-libs is myLibs). Maven: a <server> whose <id> is the <id> of the repository or mirror,
   with ${env.TELESPHOREPO_READ_USER} and ${env.TELESPHOREPO_READ_TOKEN}, in ~/.m2/settings.xml
   and in a settings file of the project that CI passes with -s.
5. Watch for these. A hosted repository holds only its own packages: keep mavenCentral(), or
   use a group with a proxy of Maven Central. A Maven group merges the versions of all its
   members, as Nexus does. Maven refuses http:// addresses other than localhost; Gradle needs
   isAllowInsecureProtocol = true for one.
6. Check: search again for the Nexus host and /repository/, and explain each hit that is left.
   Build with an empty cache (./gradlew build --refresh-dependencies, or mvn -U
   -Dmaven.repo.local=<new empty folder> verify), and check that every download comes from
   repo.example.com. If your shell lacks the token variables, ask me to run the build and send
   you the output.
7. Report: each file you changed, each Nexus address left and why, and each place you were
   unsure about.
```

   repository, Yarn 4 needs npmMinimalAgeGate: 0, or it installs a version only once it is a
   week old; on a group or a proxy, list our own packages in npmPreapprovedPackages instead. A
   plain http:// server needs its host in unsafeHttpWhitelist of Yarn.
3. Lockfiles: in package-lock.json, a Yarn 1 yarn.lock, pnpm-lock.yaml and bun.lock, change the
   prefix https://nexus.example.com/repository/<nexus name>/ to
   https://repo.example.com/npm/<telesphorepo name>/. The tarballs keep their paths
   (<name>/-/<file>.tgz) and their integrity. A Yarn 2+ yarn.lock holds no address. Then run
   the frozen install of the tool: npm ci, pnpm install --frozen-lockfile, yarn install
   --immutable or bun install --frozen-lockfile.
4. Private repositories, only if my list names one. ME: I make a read token (Settings › Tokens,
   New read token, Create token) and set it in NPM_TOKEN, here and as a CI secret. Tell me
   this name first, and never ask me for the token. Never use the name TELESPHOREPO_TOKEN: the
   CLI sets it when it publishes. Wire the variable in: .npmrc gets
   //repo.example.com/npm/<name>/:_authToken=${NPM_TOKEN}; .yarnrc.yml gets npmAlwaysAuth:
   true and npmAuthToken: "${NPM_TOKEN}". In CI, the install step gets NPM_TOKEN from a secret.
5. Watch for these. In a Telesphorepo npm group, the first member that has a package name owns
   it, and the group serves every version of that name from that member only; Nexus merges
   them. If the project needs versions of one name from two members, tell me. Telesphorepo does
   not serve npm audit: point an audit step at --registry=https://registry.npmjs.org/, or tell
   me.
6. Check: search again for the Nexus host and /repository/, and explain each hit that is left.
   Build with an empty cache (delete node_modules, then run the frozen install with an empty
   cache; for npm: npm ci --cache <new empty folder>), and check that every download comes
   from repo.example.com. If your shell lacks the token variable, ask me to run the build and
   send you the output.
7. Report: each file you changed, each Nexus address left and why, and each place you were

## The steps that need you

The agent asks for each step when it needs it. It waits until you say it is done.

- **Approve the computer.** Open the link that the agent gives you, and sign in. Check the code, click **Approve device**, and confirm with your second step.
- **Make a read token**, only for a private repository. Open **Settings › Tokens**, click **New read token**, type a name, and click **Create token**. Put it in the variables that the agent names. Never paste it to the agent.
- **Make the test repository**, for the full switch-over. Open the **Repositories** page, and click **New repository**. Make a hosted repository where your account has **Publish**.
- **Add the CI pipeline**, for the full switch-over. A server admin adds it on **Settings › People and CI › CI pipelines**, with the values that the agent gives you. For Jenkins, see also [Set up Jenkins](/publish-from-ci/#set-up-jenkins).

## After the switch-over

When your admin has [switched over](/move-from-nexus/#switch-over), follow the note in the agent's report:

<Steps>

1. Set `repo` in `telesphorepo.toml` to the real repository.

2. Check that the CI pipeline lists the real repository.

3. Publish once.

4. Delete the test repository.

</Steps>

## Use the skill

With Claude Code, you can use the skill [telesphorepo-migrate](https://github.com/Telesphorepo/Telesphorepo/tree/main/skills/telesphorepo-migrate) instead of a prompt. It asks you for the addresses and names, and finds the ecosystems in the project by itself.

<Steps>

1. Copy the skill into `~/.claude/skills/`, or into `.claude/skills/` of one project. On Windows, the user folder is `%USERPROFILE%\.claude\skills\`.

   ```sh
   git clone --depth 1 https://github.com/Telesphorepo/Telesphorepo.git /tmp/telesphorepo
   mkdir -p ~/.claude/skills
   cp -r /tmp/telesphorepo/skills/telesphorepo-migrate ~/.claude/skills/
   ```

2. Open Claude Code in the project folder, and ask:

   ```text
   Move this project from Nexus to Telesphorepo.
   ```

</Steps>
