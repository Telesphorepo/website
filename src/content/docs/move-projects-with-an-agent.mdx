To make the same changes yourself, see [Move your projects by hand](/move-projects-by-hand/).

When Telesphorepo holds a copy of your Nexus repositories (see [Copy your repositories from Nexus](/move-from-nexus/)), each project still names Nexus. A coding agent, such as Claude Code, moves a project with you: the agent changes the files, and asks you for the few steps that need a person. Choose what the project uses and how far to move it, then paste the prompt into the agent in the project folder. With Claude Code, you can also [use the skill](#use-the-skill).

Fill in the first lines of the prompt: your Telesphorepo address, your Nexus address, the name of each repository in Nexus and in Telesphorepo, and the private ones. The **Repositories** page of Telesphorepo lists the names, with a lock after each private repository. Read the changes the agent makes before you commit them.

<Path title="Gradle or Maven: download addresses only" ecosystem="gradle" scope="downloads">

```text title="Prompt: Gradle or Maven, download addresses only"
Move this project from our Nexus server to Telesphorepo. We do it together: you do every step
you can, and for each step marked ME, you tell me exactly what to do and wait until I say it is
done. Never write a password or a token into a file, a command line or this chat: read each
secret from an environment variable or a CI secret. Change files outside the project only after
I say yes. Keep every checksum and hash: the files in Telesphorepo are the same bytes as in
Nexus.

Telesphorepo: https://repo.example.com
Nexus: https://nexus.example.com
Repositories (Nexus name -> Telesphorepo name):
- maven-public -> maven-public
- maven-releases -> maven-releases
Private repositories (they need a read token): none

Scope: the download addresses only. Leave publishing on Nexus: the publish addresses, the
publish credentials and the publish steps stay as they are.

Do this:
1. Find every place that names Nexus: search every file of the repository, hidden folders too,
   for the Nexus host and for /repository/. Look in: pom.xml, .mvn/maven.config, every
   settings.xml in the project, build.gradle(.kts), settings.gradle(.kts) (pluginManagement,
   dependencyResolutionManagement), gradle.properties, gradle/*.gradle(.kts), buildSrc/,
   build-logic/, init scripts, and gradle/wrapper/gradle-wrapper.properties. Also show me what
   ~/.m2/settings.xml, ~/.gradle/gradle.properties and ~/.gradle/init.d/ on this computer name.
   Look also in CI files (.github/workflows, Jenkinsfile, .gitlab-ci.yml and others),
   Dockerfiles, compose files, shell and PowerShell scripts, and docs and READMEs. Tell me each
   Nexus repository the project uses that is not in my list, and wait for its name.
2. Change every download address to its Telesphorepo address. Address:
   https://nexus.example.com/repository/<nexus name>/ becomes
   https://repo.example.com/maven/<telesphorepo name>. The files keep their paths, so only the
   prefix changes. A <mirror> with <mirrorOf>*</mirrorOf> points at a Telesphorepo group. A
   distributionUrl on a Nexus raw repository becomes https://repo.example.com/raw/<name>/<path>;
   keep distributionSha256Sum.
3. Lockfiles: Gradle lockfiles and gradle/verification-metadata.xml hold no addresses. Keep them
   as they are.
4. Private repositories: if the list of private repositories above names one, ME: I make a read
   token. In Telesphorepo, I open Settings › Tokens, click New read token, type a name and click
   Create token. I set it, with my username, in ORG_GRADLE_PROJECT_<name>Username and
   ORG_GRADLE_PROJECT_<name>Password for Gradle, TELESPHOREPO_READ_USER and
   TELESPHOREPO_READ_TOKEN for Maven, here and as CI secrets. Tell me these names before I do
   it, and never ask me for the token. Never use the name TELESPHOREPO_TOKEN: the Telesphorepo
   CLI sets it during a publish. Wire the variables in: Gradle: in the maven { } block, name =
   "<name>" and credentials(PasswordCredentials::class) (Groovy:
   credentials(PasswordCredentials)), where <name> is the repository name as a Gradle identifier
   (my-libs is myLibs). Maven: a <server> whose <id> is the <id> of the repository or mirror,
   with ${env.TELESPHOREPO_READ_USER} and ${env.TELESPHOREPO_READ_TOKEN}, in ~/.m2/settings.xml
   and in a settings file of the project that CI passes with -s.
5. Watch for these. A hosted repository holds only its own packages: keep mavenCentral(), or use
   a group with a proxy of Maven Central. A Maven group merges the versions of all its members,
   as Nexus does. Maven refuses http:// addresses other than localhost; Gradle needs
   isAllowInsecureProtocol = true for one.
6. Check: search again for the Nexus host and /repository/, and explain each hit that is left.
   Then run a clean build with an empty cache (./gradlew build --refresh-dependencies, or mvn -U
   -Dmaven.repo.local=<new empty folder> verify), and check in its output that the downloads
   come from repo.example.com. If a private repository needs the token variables and your shell
   does not have them, ask me to run it and send you the output.
7. Report: every file you changed, each Nexus address left and why, and each place you were
   unsure about.
```

    Connect id token" with the ID telesphorepo-id-token and the audience
    https://repo.example.com. If a CI job downloads from a private repository, give its build

    group:artifact:version you published, from

    about, the CI secrets that are no longer used, and this note for the switch-over day: set
    repo in telesphorepo.toml to maven-releases, check that the CI pipeline lists

   for the Nexus host and for /repository/. Look in: .npmrc (in the project and ~/.npmrc),

   lockfiles, and the registry-url input of actions/setup-node in CI. Look also in CI files

   https://nexus.example.com/repository/<nexus name>/ becomes
   https://repo.example.com/npm/<telesphorepo name>/, with the trailing slash. Scoped registries
   (@acme:registry=) change the same way; Yarn 2 and later name them in npmRegistryServer and
   npmScopes. Remove the Nexus _auth, always-auth and email lines. Bun reads .npmrc, and
   bunfig.toml can set [install] registry and scopes. On a hosted repository, Yarn 4 needs
   npmMinimalAgeGate: 0, or it installs a version only once it is a week old; on a group or a
   proxy, list our own packages in npmPreapprovedPackages instead. A plain http:// server needs
   its host in unsafeHttpWhitelist of Yarn.
3. Lockfiles: in package-lock.json, a Yarn 1 yarn.lock, pnpm-lock.yaml and bun.lock, change the
   prefix https://nexus.example.com/repository/<nexus name>/ to
   https://repo.example.com/npm/<telesphorepo name>/. The tarballs keep their paths
   (<name>/-/<file>.tgz) and their integrity. A Yarn 2+ yarn.lock holds no address. Then run the
   frozen install of the tool: npm ci, pnpm install --frozen-lockfile, yarn install --immutable
   or bun install --frozen-lockfile.
4. Private repositories: if the list of private repositories above names one, ME: I make a read
   token. In Telesphorepo, I open Settings › Tokens, click New read token, type a name and click
   Create token. I set it, with my username, in NPM_TOKEN, here and as CI secrets. Tell me these
   names before I do it, and never ask me for the token. Never use the name TELESPHOREPO_TOKEN:
   the Telesphorepo CLI sets it during a publish. Wire the variables in: .npmrc gets
   //repo.example.com/npm/<name>/:_authToken=${NPM_TOKEN}; .yarnrc.yml gets npmAlwaysAuth: true
   and npmAuthToken: "${NPM_TOKEN}". In CI, the install step gets NPM_TOKEN from a secret.
5. Watch for these. In a Telesphorepo npm group, the first member that has a package name owns
   it, and the group serves every version of that name from that member only. Nexus merges them.
   If the project needs versions of one name from two members, tell me. Telesphorepo does not
   serve npm audit: point an audit step at --registry=https://registry.npmjs.org/, or tell me.
6. Check: search again for the Nexus host and /repository/, and explain each hit that is left.
   Then run a clean build with an empty cache (delete node_modules, then run the frozen install
   of the tool with an empty cache (for npm: npm ci --cache <new empty folder>)), and check in
   its output that the downloads come from repo.example.com. If a private repository needs the
   token variables and your shell does not have them, ask me to run it and send you the output.
7. Report: every file you changed, each Nexus address left and why, and each place you were
   unsure about.

## The steps that need you

The agent asks for each of these when it needs it, and waits until you say it is done.

- **Approve the computer** (full switch-over, and Docker pulls from a private repository). The agent runs `telesphorepo login` and gives you a link and a code. Open the link, sign in, check the code, click **Approve device**, and confirm with your second step. With single sign-on, you sign in again at your provider. After that, the computer can publish to every repository where your account has **Publish**.
- **Make a read token** (only for a private repository). **Settings** › **Tokens** › **New read token**. Type a name, then click **Create token**. Put it in the environment variables that the agent names, on your computer and as CI secrets. Do not paste it to the agent.
- **Make the rehearsal repository** (full switch-over). See [Rehearse publishing](#rehearse-publishing).
- **Add the CI pipeline** (full switch-over). On **Settings** › **People and CI** › **CI pipelines**, add the pipeline of the project with the values that the agent gives you, and list the rehearsal repository and the real one. A server admin does this. For Jenkins, also install the plugin **OpenID Connect Provider** and add the credential `telesphorepo-id-token`, as in [Set up Jenkins](/publish-from-ci/#set-up-jenkins).

## Rehearse publishing

The copies of Nexus refuse uploads until the switch-over, so that Nexus and Telesphorepo do not part ways. With a prompt for the full switch-over, the agent publishes to a test repository, such as `maven-releases-rehearsal`, and checks the result with you. You make the test repository and give your account and the CI pipeline **Publish** on it. [Rehearse publishing](/move-projects-by-hand/#rehearse-publishing) has each step.

After the [switch-over](/move-from-nexus/), follow the note that the agent leaves in its report: set `repo` in the project's `telesphorepo.toml` to the real repository, check that the CI pipeline lists the real repository, publish again, then delete the test repository.

<Aside>
A rehearsal also checks your CI pipeline: the trust policy, the identity token and the CLI install step. These do not depend on the repository.
</Aside>

## Use the skill

The skill [telesphorepo-migrate](https://github.com/Telesphorepo/Telesphorepo/tree/main/skills/telesphorepo-migrate) holds the same steps for every ecosystem in one file. With it, Claude Code asks you for the addresses, the scope and the repository names, finds the ecosystems in the project by itself, and follows the same steps as the prompts.

Copy the folder into `~/.claude/skills/` for every project, or into `.claude/skills/` of one project:

```sh
git clone --depth 1 https://github.com/Telesphorepo/Telesphorepo.git /tmp/telesphorepo
mkdir -p ~/.claude/skills
cp -r /tmp/telesphorepo/skills/telesphorepo-migrate ~/.claude/skills/
```

On Windows, the user folder is `%USERPROFILE%\.claude\skills\`. Then open Claude Code in the project folder and ask, for example:

```text
Move this project from Nexus to Telesphorepo.
```
