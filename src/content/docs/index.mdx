<ul class="tr-features not-content">
    <li>
        <span class="tr-label">Deploy</span>
        <h3>One binary, one container</h3>
        <p>The server, the web UI and the SQLite database run in one process. A container with a <code>/data</code> volume is the whole install. Settings change in the UI and apply without a restart.</p>
    </li>
    <li>
        <span class="tr-label">Publish</span>
        <h3>No long-lived secrets in CI</h3>
        <p>Every upload needs a publish session: a credential for one repo that ends after 15 minutes by default. GitHub Actions and Jenkins get sessions with their OIDC tokens through trust policies. A laptop approves a device once with a second factor.</p>
    </li>
    <li>
        <span class="tr-label">Store</span>
        <h3>Filesystem or S3, moved live</h3>
        <p>Keep blobs on local disk or in any S3-compatible bucket, such as Cloudflare R2, SeaweedFS or AWS. Change the storage in Settings and the server copies every blob in the background. Reads and uploads continue during the move.</p>
    </li>
    <li>
        <span class="tr-label">Migrate</span>
        <h3>Warm cut-over from Nexus</h3>
        <p>Add a Nexus 3 server as a source. Telesphorepo mirrors the hosted repos you pick with repeated syncs and keeps them read only. Cut over when you are ready to publish here.</p>
    </li>
</ul>

## Quickstart

Build the image from the source and start it with a volume for `/data`. The build runs in Docker, so you need only Docker or Podman.

```sh
git clone https://github.com/Telesphorepo/Telesphorepo
cd Telesphorepo
docker build -t telesphorepo:local .
docker run -d --name telesphorepo -p 8080:8080 -v telesphorepo-data:/data telesphorepo:local
```

On the first start, the server prints a generated `admin` password once to the container log. Read it, then open `http://localhost:8080` and sign in.

```sh
docker logs telesphorepo
```
