## Every publish gets its own ticket

<div class="tr-split">
<div>

In many setups, a CI job holds a deploy password that never changes. Here, no long-lived credential can write. The client proves who it is, and the server issues a publish session: a token for one repo that ends after 15 minutes.

The Gradle plugin and the Maven extension do this on every publish, so you do not see it. GitHub Actions and Jenkins use their own identity tokens, so a CI job has no secret to leak. The publish log keeps every session for 30 days after it ends.

## As fast at a million files as at a hundred thousand

Every query on a request path uses an index, and lists page with keys, not offsets. So a request costs the same in a large repo as in a small one. The scale test checks this on every run of `go tool task test scale`. It seeds 100k synthetic assets, measures, seeds up to 1M, and measures again.

<ScaleTest />

## One image. Nothing else to run.

There is no database server and no search cluster. Search runs on an SQLite full-text index. The server, the web UI and the database run in one process. Settings live in the database and apply without a restart. To move the files from local disk to a bucket, change the storage on the Settings page. The server copies every file in the background while reads and uploads continue.

<Install />

Start the image with a volume for `/data`:

```sh
docker run -d --name telesphorepo -p 8080:8080 -v telesphorepo-data:/data ghcr.io/telesphorepo/telesphorepo:latest
```

On the first start, the server prints a generated `admin` password once to the container log. Read it, then open `http://localhost:8080` and sign in.

```sh
docker logs telesphorepo
```

Binaries for Linux, macOS and Windows are on the [GitHub Releases](https://github.com/Telesphorepo/Telesphorepo/releases) page. The [install guide](/getting-started/install/) has the other ways to run it.

## Leaving Nexus? Bring your repos with you.

Nexus 3 needs a JVM and a database to run, and some of its upgrades are projects of their own. The move from OrientDB to H2 is one example: [its issue](https://github.com/sonatype/nexus-public/issues/449) was opened in 2024 and is still open.

To move, add your Nexus 3 server as a source and pick its hosted repos. Telesphorepo mirrors them with repeated syncs and keeps them read only until you cut over. It only reads from Nexus, so Nexus keeps serving your builds the whole time. When you are ready, cut over: one last sync, and the repos are yours to publish to.
