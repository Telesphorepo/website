## A publish, from proof to close

In many setups, a CI job holds a deploy password that never changes. Here, no long-lived credential can write. The client proves who it is, and the server issues a session for one repo. The Gradle plugin and the Maven extension do this on every publish, so you do not see it. GitHub Actions and Jenkins use their own identity tokens, so a CI job has no secret to leak.

<PublishSession />

Read [how publishing works](/publishing/overview/), then set up the [Gradle plugin](/publishing/gradle-plugin/), the [Maven extension](/publishing/maven-extension/) or [GitHub Actions](/publishing/github-actions/).

## The whole install

There is no database server and no search cluster. Search runs on an SQLite full-text index. The server, the web UI and the database run in one process. Settings live in the database and apply without a restart. To move the files from local disk to a bucket, change the storage on the Settings page. The server copies every blob in the background while reads and uploads continue.

## The 1M-asset test

Every query on a request path uses an index, and lists page with keys, not offsets. So a request costs the same with a large repo as with a small one. The scale test checks this on every run of `go tool task test scale`. It seeds 100k synthetic assets, measures, seeds up to 1M, and measures again.

<ScaleTest />

## Leave Nexus without a freeze

Add a Nexus 3 server as a source and pick its hosted repos. Telesphorepo mirrors them with repeated syncs and keeps them read only until you cut over. Telesphorepo only reads from Nexus, so Nexus keeps serving your builds the whole time. When you are ready, cut over: one last sync, and the repos are yours to publish to.

<NexusCutover />

The [Nexus migration guide](/operations/nexus-migration/) has the format mapping and the failure rules.

## Quickstart

Build the image from the source and start it with a volume for `/data`. The build runs in Docker, so you need only Docker or Podman.

```sh
git clone https://github.com/Telesphorepo/Telesphorepo
cd Telesphorepo
docker build -t telesphorepo:local .
docker run -d --name telesphorepo -p 8080:8080 -v telesphorepo-data:/data telesphorepo:local
```

On the first start, the server prints a generated `admin` password once to the container log. Read it, then open `http://localhost:8080` and sign in.

```sh
docker logs telesphorepo
```
