Create the repository first. Open **Settings** › **Repositories** › **New repository**, and choose the format **Debian (apt)** or **Raw files**.

To upload with `curl`, you need a publish token:

<Steps>

1. Open **Settings** › **Tokens**, and click **New publish token**.
2. Choose the repository, and click **Continue**.
3. Confirm with your second factor, and click **Create token**.
4. Copy the token. It starts with `trs_` and works for 15 minutes.

</Steps>

Publish tokens are for accounts with a password and **Publish** on the repository. You can also upload in the browser: open the repository and click **Upload**.

## Debian

The examples use a Debian repository named `apt`.

<Steps>

1. Upload a package. The path names the distribution (`stable`) and the component (`main`). Paste the publish token at the hidden prompt, so it stays out of the shell history and the process list.

   ```sh
   printf 'Publish token: '; read -rs TOKEN; echo
   printf 'user = "publish:%s"\n' "$TOKEN" | curl -fsS -K - -T my-package_1.0.0_amd64.deb \
     https://repo.example.com/debian/apt/upload/stable/main
   ```

   The server builds and signs the indexes about 2 seconds later.

2. On each machine that installs, add the key and the source:

   ```sh
   sudo mkdir -p /etc/apt/keyrings
   sudo curl -fsSL https://repo.example.com/debian/apt/key.asc -o /etc/apt/keyrings/telesphorepo.asc
   echo "deb [signed-by=/etc/apt/keyrings/telesphorepo.asc] https://repo.example.com/debian/apt stable main" \
     | sudo tee /etc/apt/sources.list.d/telesphorepo.list
   ```

3. Install:

   ```sh
   sudo apt update
   sudo apt install my-package
   ```

</Steps>

<details>
<summary>Private Debian repository</summary>

apt needs your username and a read token. Create the token under **Settings** › **Tokens** › **New read token**. It starts with `trp_`. Each command below asks for the token at a hidden prompt.

Download the key with the token:

```sh
printf 'Read token: '; read -rs READ_TOKEN; echo
printf 'user = "YOUR_USERNAME:%s"\n' "$READ_TOKEN" \
  | sudo curl -fsSL -K - https://repo.example.com/debian/apt/key.asc -o /etc/apt/keyrings/telesphorepo.asc
```

Give apt the token. The `install` command makes the file readable by root only before the token goes in. `tee` writes to the file only, not to the terminal.

```sh
printf 'Read token: '; read -rs READ_TOKEN; echo
sudo install -m 600 /dev/null /etc/apt/auth.conf.d/apt.conf
printf 'machine %s login YOUR_USERNAME password %s\n' https://repo.example.com/debian/apt "$READ_TOKEN" \
  | sudo tee -a /etc/apt/auth.conf.d/apt.conf > /dev/null
```

</details>

<details>
<summary>Architectures and upload errors</summary>

A new Debian repository takes the architectures `amd64` and `arm64`, and packages for `all`. Change the list in **Architectures** on the **Format settings** tab of the repository settings. An upload with another architecture fails. The server builds the package lists of an added architecture, and removes those of a removed one.

An upload of the same package and version with other bytes answers `409`. Raise the version.

</details>

## Raw files

A raw repository keeps any file at any path. The examples use a raw repository named `files`.

Upload:

```sh
printf 'Publish token: '; read -rs TOKEN; echo
printf 'user = "publish:%s"\n' "$TOKEN" | curl -fsS -K - -T app-1.2.0.tar.gz \
  https://repo.example.com/raw/files/app/app-1.2.0.tar.gz
```

Download:

```sh
curl -fL -O https://repo.example.com/raw/files/app/app-1.2.0.tar.gz
```

For a private repository, give `curl` your username and a read token on stdin:

```sh
printf 'Read token: '; read -rs READ_TOKEN; echo
printf 'user = "YOUR_USERNAME:%s"\n' "$READ_TOKEN" \
  | curl -fL -K - -O https://repo.example.com/raw/files/app/app-1.2.0.tar.gz
```

<details>
<summary>Replace a file</summary>

By default, a raw repository refuses other bytes at a path that exists. It answers `409`. To allow a replace, open the repository settings, then the **Format settings** tab. In **Replace files**, choose `allow`, then click **Save**.

</details>

## Maven files with curl

Upload a file to a Maven repository with a publish token:

```sh
printf 'Publish token: '; read -rs TOKEN; echo
printf 'user = "publish:%s"\n' "$TOKEN" | curl -fsS -K - -T my-lib-1.0.0.jar \
  https://repo.example.com/maven/releases/com/example/my-lib/1.0.0/my-lib-1.0.0.jar
```

## Publish with curl from CI

A CI job trades its identity token for a publish token, then uploads. An admin adds a CI pipeline for the job first, as in [Run the server](/run-the-server/#add-a-ci-pipeline). The scripts need `curl` and `jq`.

<Tabs>
<TabItem label="GitHub Actions">

```yaml title=".github/workflows/publish.yml"
on:
  push:
    tags: ["v*"]

permissions:
  id-token: write
  contents: read

jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - name: Publish to releases
        run: |
          OIDC=$(printf 'header = "Authorization: Bearer %s"\n' "$ACTIONS_ID_TOKEN_REQUEST_TOKEN" \
            | curl -fsS -K - "$ACTIONS_ID_TOKEN_REQUEST_URL&audience=https://repo.example.com" | jq -r .value)
          echo "::add-mask::$OIDC"
          SESSION=$(printf '{"token":"%s","repo":"releases"}' "$OIDC" \
            | curl -fsS -H 'Content-Type: application/json' --data @- https://repo.example.com/api/publish/sessions/oidc)
          TOKEN=$(echo "$SESSION" | jq -r .token)
          echo "::add-mask::$TOKEN"
          ID=$(echo "$SESSION" | jq -r .id)
          printf 'user = "publish:%s"\n' "$TOKEN" | curl -fsS -K - -T my-lib-1.0.0.jar https://repo.example.com/maven/releases/com/example/my-lib/1.0.0/my-lib-1.0.0.jar
          printf 'user = "publish:%s"\n' "$TOKEN" | curl -fsS -K - -X DELETE https://repo.example.com/api/publish/sessions/$ID
```

</TabItem>
<TabItem label="Jenkins">

```groovy title="Jenkinsfile"
pipeline {
  agent any
  stages {
    stage('Publish to releases') {
      steps {
        // The token is good for 10 minutes, so only this stage gets it.
        withCredentials([string(credentialsId: 'telesphorepo-id-token', variable: 'OIDC_TOKEN')]) {
          sh '''
            set +x
            SESSION=$(printf '{"token":"%s","repo":"releases"}' "$OIDC_TOKEN" \\
              | curl -fsS -H 'Content-Type: application/json' --data @- https://repo.example.com/api/publish/sessions/oidc)
            TOKEN=$(echo "$SESSION" | jq -r .token)
            ID=$(echo "$SESSION" | jq -r .id)
            close_session() { printf 'user = "publish:%s"\\n' "$TOKEN" | curl -fsS -K - -X DELETE https://repo.example.com/api/publish/sessions/$ID; }
            trap close_session EXIT
            printf 'user = "publish:%s"\\n' "$TOKEN" | curl -fsS -K - -T my-lib-1.0.0.jar https://repo.example.com/maven/releases/com/example/my-lib/1.0.0/my-lib-1.0.0.jar
          '''
        }
      }
    }
  }
}
```

The Jenkins credential `telesphorepo-id-token` comes from the plugin **OpenID Connect Provider**, with the audience `https://repo.example.com`.

</TabItem>
</Tabs>

The `DELETE` request ends the token. If you skip it, the token ends by itself after 15 minutes.

Each script gives every token to `curl` on stdin, so no token is an argument of a process. The workflow hides each token in the job log with `::add-mask::`. The Jenkins script starts with `set +x` to keep the token out of the build log, and its `trap` ends the token also when the upload fails.
