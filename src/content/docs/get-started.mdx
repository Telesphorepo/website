## Run the server

<Path title="Docker" engine="docker" level={3}>

<Steps>

1. Run this.

   ```sh
   docker run -d --name telesphorepo -p 8080:8080 -v telesphorepo-data:/data ghcr.io/telesphorepo/telesphorepo:latest
   ```

2. Run this, and copy the admin password that it shows.

   ```sh
   docker logs telesphorepo
   ```

</Steps>

</Path>

<Path title="Podman" engine="podman" level={3}>

<Steps>

1. Run this.

   ```sh
   podman run -d --name telesphorepo -p 8080:8080 -v telesphorepo-data:/data ghcr.io/telesphorepo/telesphorepo:latest
   ```

2. Run this, and copy the admin password that it shows.

<Path title="Download the program" engine="binary" level={3}>

<Steps>

1. Download and unpack the file for your system from [GitHub Releases](https://github.com/Telesphorepo/Telesphorepo/releases).

2. Run this, and copy the admin password that it shows.

   ```sh
   ./telesphorepo serve
   ```

</Steps>

</Path>

## Make a repository

<Steps>

1. Open `http://localhost:8080` and sign in as `admin`.

2. Add your phone app when the page asks for it.

   **Authenticator app** › **Add**. Scan the code, then type the code from your phone.

3. Make a repository named `releases`.

   **Settings** › **Repositories** › **New repository**. Type `releases`, choose **Maven / Gradle**, and click **Create repository**.

</Steps>

## Publish

<Path title="Gradle (Kotlin)" tool="gradle-kts" level={3}>

<Steps>

1. Paste this at the top of `settings.gradle.kts`.

   ```kotlin title="settings.gradle.kts"
   plugins {
       id("com.telesphorepo.publish") version "0.1.0"
   }

   telesphorepo {
       url = "http://localhost:8080"
       repository = "releases"
   }
   ```

2. Give your project a group and a version in `build.gradle.kts`.

   ```kotlin title="build.gradle.kts"
   group = "com.example"
   version = "1.0.0"
   ```

3. Run this.

   ```sh
   ./gradlew publish
   ```

4. Click **Approve device** in the browser page that opens.

</Steps>

Done when Gradle prints `BUILD SUCCESSFUL`. Your package is now on the **Files** tab of `releases`.

</Path>

<Path title="Maven" tool="maven" level={3}>

<Steps>

1. Create `.mvn/extensions.xml` with this.

   ```xml title=".mvn/extensions.xml"
   <extensions>
     <extension>
       <groupId>com.telesphorepo</groupId>
       <artifactId>telesphorepo-maven-extension</artifactId>
       <version>0.1.0</version>
     </extension>
   </extensions>
   ```

2. Create `.mvn/maven.config` with this.

   ```text title=".mvn/maven.config"
   -Dtelesphorepo.url=http://localhost:8080
   ```

3. Paste this into `pom.xml`, inside `<project>`.

   ```xml title="pom.xml"
   <distributionManagement>
     <repository>
       <id>releases</id>
       <url>http://localhost:8080/maven/releases</url>
     </repository>
     <snapshotRepository>
       <id>releases</id>
       <url>http://localhost:8080/maven/releases</url>
     </snapshotRepository>
   </distributionManagement>
   ```

4. Run this.

   ```sh
   mvn deploy
   ```

5. Click **Approve device** in the browser page that opens.

</Steps>

Done when Maven prints `BUILD SUCCESS`. Your package is now on the **Files** tab of `releases`.

</Path>

Next, let your team [publish](/publish/) and [download](/download/). Before other people use the server, read [Run in production](/production/).

## If something goes wrong

<details>
<summary>Find your problem, then do the fix</summary>

**The logs show no password.** Wait a few seconds, then run the logs command again.

**You lost the admin password.** Run `docker exec -it telesphorepo /telesphorepo user passwd admin`, and type a new one.

**You want to pick the first admin yourself.** Set `TR_BOOTSTRAP_ADMIN_USER` and `TR_BOOTSTRAP_ADMIN_PASSWORD` on the first start. The server reads them only while it has no users.

**Your data is gone after you removed the container.** Always keep the `telesphorepo-data` volume. It holds the database, the files and the key for your secret settings.

**You run the program and want to know where the data is.** It is in `./data`, next to where you started it.

**Which image tags and systems are there?** The image runs on `linux/amd64` and `linux/arm64`. Each release has the tags `X.Y.Z` and `X.Y`, and `latest` is the newest. Check a downloaded program against `SHA256SUMS` on the release page.

**Gradle or Maven gives an error.** See [Publish › If something goes wrong](/publish/#if-something-goes-wrong).

</details>
