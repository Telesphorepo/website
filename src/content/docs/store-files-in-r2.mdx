The server keeps files on its local disk. Move them to a bucket when the disk is not enough: Cloudflare R2 charges nothing for downloads, and AWS S3 and SeaweedFS work too.

## Store files in Cloudflare R2

<Place where="In Cloudflare, then in Telesphorepo" />

<Steps>

1. In Cloudflare, create a bucket.

2. Create an R2 API token with **Object Read & Write** on the bucket. Copy its two keys: Cloudflare shows them once.

</Steps>

<Place where="In Telesphorepo" />

<Steps>

3. Open **Settings** › **Storage**.

4. Under **Storage type**, choose **A Cloudflare R2 bucket, or another S3-compatible bucket**.

5. Fill in the bucket.

   | Field | Value |
   |---|---|
   | **Address** | The **S3 API** address from the bucket's **Settings** page in Cloudflare, such as `https://<account id>.r2.cloudflarestorage.com` |
   | **Region** | Empty |
   | **Bucket** | The name of the bucket |
   | **Access key ID** and **Secret access key** | The two keys of the token |

6. Click **Test connection**. A line tells you whether the server reached the bucket.

7. Click **Save** in the bar at the bottom, then confirm with **Start the move**.

</Steps>

<Done>Done when the move on **Settings** › **Storage** has finished and the page names your bucket.</Done>

The server copies the files to the bucket in the background, and everything keeps working meanwhile. The old files stay on the disk, so delete them when the bucket works.

## Who sends the bytes

| Setup | Who checks each download | Who sends the bytes |
|---|---|---|
| Local disk | your server | your server |
| R2 | your server | R2 |
| R2 and [edge delivery](https://github.com/Telesphorepo/Telesphorepo/tree/main/edge) | a Cloudflare Worker near the build | R2, from the nearest bucket |

## Use AWS S3 or SeaweedFS

Follow the same steps, with these values in the form.

| Field | AWS S3 | SeaweedFS |
|---|---|---|
| **Address** | Empty | `http://seaweedfs:8333` |
| **Region** | The bucket's region, such as `us-east-1` | Any name, such as `us-east-1` |
| **Path-style addresses** | Off | On |

## Troubleshooting

<details>
<summary>Test connection fails with R2</summary>

Use the **S3 API** address, with nothing after the host. A custom domain of the bucket does not work here.

</details>

<details>
<summary>Builds cannot download from the bucket</summary>

Turn off **Download from the bucket**, then click **Save**. Your server then sends the bytes itself.

</details>
