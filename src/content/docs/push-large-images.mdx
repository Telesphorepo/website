Behind Cloudflare (Free and Pro plans), each image layer must be under 100 MB, while pulls have no limit. A second address lets the layers skip Cloudflare: people still push to the main address, and the server sends the layers to the upload address. A server that is not behind Cloudflare needs none of this.

## Add an upload address

:::caution
This makes the IP address of your server public.
:::

<Place where="In Cloudflare, then on the host of the server" />

<Steps>

1. In Cloudflare, add a second name for your server, such as `upload.example.com`. Make the record **DNS only**.

2. Serve that name over HTTPS too, as in [Serve over HTTPS](/run-the-server/#serve-over-https). With Caddy, list both names in the Caddyfile on the host of the server.

   ```text title="/etc/caddy/Caddyfile"
   repo.example.com, upload.example.com {
       reverse_proxy localhost:8080
   }
   ```

3. In the firewall of your server, open the HTTPS port for the computers that push.

</Steps>

<Place where="In Telesphorepo" />

<Steps>

4. Open **Settings** › **General**. Under **Docker**, set **Docker upload address** to `https://upload.example.com`.

5. Turn on **Expose the origin IP for Docker uploads**, then click **Save** in the bar at the bottom.

</Steps>

<Done>Done when a push of a layer over 100 MB succeeds.</Done>

## Push with ORAS and Helm 4

ORAS and Helm 4 send layers only to the address in the command, so push to the upload address.

<Place where="In a terminal on your computer" />

```sh
helm push mychart-0.1.0.tgz oci://upload.example.com/docker
oras push upload.example.com/docker/team/art:1.0 file.txt
```

## Troubleshooting

<details>
<summary>A push stops with `413` behind Cloudflare</summary>

The layer is over 100 MB. Add an [upload address](#add-an-upload-address).

</details>

<details>
<summary>A push of a layer over 2 GiB fails</summary>

The server takes files up to its **Max upload size**, 2 GiB by default. Raise it on **Settings** › **General**, then click **Save**.

</details>
