## Add people and give access

<Steps>

1. Open **Settings**, then **People**, and click **New account**. Enter a username and a password, then click **Create account**.
2. On the page of the person, click **Give access**. Tick the repositories and choose **Download** or **Publish**.

</Steps>

**Publish** includes **Download**. Admins can reach every repository.

You can also add people from the command line, on the machine of the server:

```sh
docker exec -it telesphorepo /telesphorepo user add alice
docker exec -it telesphorepo /telesphorepo user add bob --admin
```

## Two-step verification

Two-step verification protects the actions that matter:

- Admins need it to sign in.
- Everyone needs it to approve a computer and to create a publish token.

Each person sets it up under **Settings**, **Sign-in and security**. Add an authenticator app or a passkey. Then create recovery codes and keep them in a safe place.

<Aside type="caution">
Passkeys need the **Public base URL**. Set it before anyone adds a passkey. If the host of the address changes later, the passkeys stop working.
</Aside>

<details>
<summary>Someone lost every second factor</summary>

Remove the factors of the person on the machine of the server:

```sh
docker exec -it telesphorepo /telesphorepo user reset-2fa alice
```

The person sets up a new factor at the next sign-in.

</details>

<details>
<summary>Someone forgot the password</summary>

An admin can set a new password on the page of the person, with **Reset password**. Or use the command line:

```sh
docker exec -it telesphorepo /telesphorepo user passwd alice
```

</details>

## Single sign-on for admins

Admins can sign in through an OpenID Connect provider, such as Keycloak, Entra ID or Google. Every person who signs in this way is an admin. People who publish keep accounts with a password.

<Steps>

1. At your provider, create a confidential client with the redirect address `https://repo.example.com/api/auth/oidc/callback`.
2. At your provider, create a group for the admins, for example `telesphorepo-admins`. Make the ID token carry the groups in a `groups` claim.
3. Open **Settings**, then **Sign-in options**. Enter the issuer URL, the client ID and the client secret. Click **Test**.
4. Under the admin rule, enter the group `telesphorepo-admins`. You can also list admin emails.
5. Save. The sign-in page now offers single sign-on.

</Steps>

<details>
<summary>Turn off password sign-in for admins</summary>

When single sign-on works, you can turn off **Password sign-in for admins** on the **Sign-in options** page. Sign in once through single sign-on first.

If single sign-on breaks later, start the server with `-e TR_ADMIN_PASSWORD_LOGIN=true`. The local admin can then sign in with the password again.

</details>

<details>
<summary>Keycloak: the groups claim</summary>

Add a **Group Membership** mapper to the client scope of the client. Turn off **Full group path**, so that the value is `telesphorepo-admins` and not `/telesphorepo-admins`.

</details>
