The server backs itself up into the `/backups` volume every 24 hours and keeps the newest 7, so a restore needs only the volume and a command. Put the volume on another disk if you can.

## Back up

A backup holds the database, the master key and the stored files. With R2 or S3, the files stay in the bucket, so back up the bucket too, with its versioning or replication.

To back up now:

<Place where="In Telesphorepo" />

<Steps>

1. Open **Settings** › **Backups**.

2. Click **Back up now**.

</Steps>

<Done>Done when the new backup appears under **Kept backups**.</Done>

### Back up from the command line

This works while the server runs.

<Place where="On the host of the server, in a terminal" />

```sh
docker run --rm -v telesphorepo-data:/data -v telesphorepo-backups:/backups \
  ghcr.io/telesphorepo/telesphorepo:latest backup /backups
```

## Keep the master key safe

The master key encrypts the secret settings. The server keeps it in the data volume, and each backup holds a copy. To keep it out of the volume instead, give the server the key in `TR_MASTER_KEY`.

<Place where="On the host of the server, in a terminal" />

<Steps>

1. Before the first start, make a key and save it in a file that only root can read, such as `/etc/telesphorepo/master.key`.

   ```sh
   sudo mkdir -p /etc/telesphorepo
   openssl rand -base64 32 | sudo tee /etc/telesphorepo/master.key > /dev/null
   sudo chmod 600 /etc/telesphorepo/master.key
   ```

2. Pass it to the server in `TR_MASTER_KEY`.

   ```sh
   docker run -d --name telesphorepo -p 127.0.0.1:8080:8080 \
     -v telesphorepo-data:/data -v telesphorepo-backups:/backups \
     -e TR_MASTER_KEY="$(sudo cat /etc/telesphorepo/master.key)" \
     ghcr.io/telesphorepo/telesphorepo:latest
   ```

</Steps>

<Done>Done when a backup on **Settings** › **Backups** shows the **No master key** badge, because the backup holds no key.</Done>

Keep a copy of the key where you keep the backups: a backup cannot be restored without it. Never change the key later.


## Restore

A restore copies a backup into a new, empty volume and starts the server on it.

<Place where="In Telesphorepo" />

<Steps>

1. On **Settings** › **Backups**, point at the date of a backup to see its folder name, such as `20261020T201500.123Z`. If the server is down, the folder name is the name of a folder in the `/backups` volume.

</Steps>

<Place where="On the host of the server, in a terminal" />

<Steps>

2. Remove the server container.

   ```sh
   docker rm -f telesphorepo
   ```

3. Restore the backup into a new, empty volume.

   ```sh
   docker run --rm -v telesphorepo-backups:/backups -v telesphorepo-restored:/data \
     ghcr.io/telesphorepo/telesphorepo:latest restore /backups/20261020T201500.123Z
   ```

4. Start the server on that volume.

   ```sh
   docker run -d --name telesphorepo -p 127.0.0.1:8080:8080 \
     -v telesphorepo-restored:/data -v telesphorepo-backups:/backups \
     ghcr.io/telesphorepo/telesphorepo:latest
   ```

</Steps>

<Done>Done when you can sign in to the server and your repositories and people are there.</Done>

## Troubleshooting

<details>
<summary>The Backups page says backups are off</summary>

The downloaded program has no backup folder. Set **Folder** on **Settings** › **Backups**.

</details>

<details>
<summary>The restore says the backup is from a newer version</summary>

Start the server with the image of the version that the restore names.

</details>
