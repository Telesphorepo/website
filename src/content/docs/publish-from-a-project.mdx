Set up a project once with one line from the web UI, then publish it with `telesphorepo publish`. The CLI runs the publish command of your own build tool, so you add no repository address and no password to the build.

## Set up the project

If the project folder holds `telesphorepo.toml` already, someone set it up: pull the latest commit, and go on to [Publish](#publish). To publish from GitHub Actions or Jenkins, follow [Publish from CI](/publish-from-ci/) instead: it runs the same line.

<Place where="In Telesphorepo, then in a terminal in the project folder" />

<Steps>

1. In Telesphorepo, open your repository, then its **Publish to this repository** tab. Click **Set up a project**, and confirm with your second step. The page shows the setup line: one command that installs the CLI and sets up the project.

2. Copy the setup line from the page. Open a terminal in the project folder, paste the line, and press Enter. The page shows the line for the system of your browser, with a switch for the other. The line works once, for 10 minutes.

3. The CLI approves this computer, writes `telesphorepo.toml` and asks "Add a CI file that publishes to your-repo?". Press Enter to take "1) No CI file".

</Steps>

<Done>Done when the CLI prints "Wrote" and the path of `telesphorepo.toml`.</Done>

## Commit the files

Commit `telesphorepo.toml` and push it. The file holds no secret. Your teammates and CI read it, so they publish to the same repository.

```sh
git add telesphorepo.toml
git commit -m "Publish to Telesphorepo"
git push
```

## Publish

<Place where="In a terminal in the project folder" />

<Steps>

1. Run the publish. The CLI prints the command of your build tool, such as `mvn deploy`, then runs it.

   ```sh
   telesphorepo publish
   ```

2. If you got `telesphorepo.toml` from a teammate's commit and never ran the setup line on this computer, the CLI prints "This computer has no device of" and your server's address, then a link and a code. Open the link, check that the page shows the same code, and click **Approve device**.

</Steps>

<Done>Done when your build tool says the publish worked, and the **Files** tab of the repository shows the new version.</Done>

To see the command without a publish, run `telesphorepo status`. For a Debian or raw repository, name the files:

```sh
telesphorepo publish app-1.2.0.tar.gz
```

## Related tasks

### Send releases and snapshots to different repositories

Add a rule to `telesphorepo.toml`. The CLI reads the version of the project, and a version that matches the rule goes to its repository, so you never edit the file for a release. The rules are in [Publish by version](/cli/#publish-by-version).

<Fill />

```toml title="telesphorepo.toml"
server = "https://your-server"
repo = "maven-releases"

[[when]]
version = "*-SNAPSHOT"
repo = "maven-snapshots"
```

### Publish to more than one repository

A `telesphorepo.toml` names one repository. When one git repository publishes to two, such as jars and a Debian package, give each its own folder with its own `telesphorepo.toml`, and run `telesphorepo publish` in each folder.

### Push Docker images

A Docker repository needs no `telesphorepo.toml`: Docker gets a token from the credential helper of the CLI at each push, so you run no `docker login`. Podman, Helm and ORAS use the same helper. Set it up once on each computer.

<Place where="In Telesphorepo, then in a terminal" />

<Steps>

1. [Set up the project](#set-up-the-project) on the Docker repository, as above.

2. When the CLI asks "Add the credential helper to" and the path of your Docker config file, type `y` and press Enter.


3. Tag the image with the host name of your server and the name of the repository, then push it.

   ```sh
   docker push your-server/your-repo/app:1.0
   ```

</Steps>

<Done>Done when `docker push` prints the digest of the image.</Done>

### Set it up by hand

Use this when you cannot run the setup line.

<Place where="In a terminal in the project folder" />

<Steps>

1. [Install the CLI](/install-cli/).

2. Approve this computer. Open the link that the CLI prints, sign in, and approve the code.

   ```sh
   telesphorepo login https://your-server
   ```

3. Create `telesphorepo.toml` in the project folder, and commit it. Some repositories need more keys, such as `path` for raw: see [telesphorepo.toml](/cli/#telesphorepotoml).

   ```toml title="telesphorepo.toml"
   server = "https://your-server"
   repo = "your-repo"
   ```

</Steps>

<Done>Done when `telesphorepo status` shows the approval and the project.</Done>

To publish with the build tool's own command instead, open **Set it up by hand** on the **Publish to this repository** tab.

## Troubleshooting

<details>
<summary>The CLI does not find a project</summary>

Run the line in the folder that holds the project file, such as `pom.xml` or `package.json`. The CLI names the files that it looks for.

</details>

<details>
<summary>`no telesphorepo.toml in this folder or above`</summary>

[Set up the project](#set-up-the-project), or pull the latest commit.

</details>

<details>
<summary>The setup line was used or ended</summary>

A line works once, for 10 minutes. Click **Make another line** on the tab for a new one.

</details>

<details>
<summary>`Warning: git ignores telesphorepo.toml`</summary>

Then CI and your teammates do not get the file. Remove the line that the warning names from `.gitignore`, or run `git add -f telesphorepo.toml`.

</details>

<details>
<summary>No browser page opens, or it asks for two-step verification</summary>

Copy the address from the terminal, and open it yourself. If the page asks for two-step verification, click **Set up two-step verification**, add your phone app, then approve.

</details>

<details>
<summary>The server refused the device</summary>

An approval lasts 90 days, unless someone removes the device. Run `telesphorepo login https://your-server`, and approve again.

</details>

<details>
<summary>The CLI says that a tool is not on the PATH</summary>

Install the build tool of the project, such as `pnpm`, `poetry` or `dotnet`. Then publish again.

</details>

<details>
<summary>403 when you publish</summary>

You cannot publish to this repository yet. Ask your server admin for **Publish** on it.

</details>

<details>
<summary>409 when you publish</summary>

That version is on the server already. Raise the version, then publish again.

</details>

<details>
<summary>You want to take a version back</summary>

Open the repository's **Files** tab, and delete the files of that version. You need **Delete files** on the repository.

</details>

<details>
<summary>The CLI says that it needs a newer CLI or a newer server</summary>

For a newer CLI, press Enter to update, or run `telesphorepo update`. For a newer server, ask your server admin.

</details>
