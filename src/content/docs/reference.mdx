## Commands

| Command | What it does |
|---|---|
| `telesphorepo serve` | Runs the server. `telesphorepo` with no command does the same. |
| `telesphorepo dev` | Runs a local server with demo repositories and demo data. Add `--empty` for empty repositories. |
| `telesphorepo user add NAME [--admin]` | Creates a user. It asks for the password. |
| `telesphorepo user passwd NAME` | Sets a new password and signs the user out everywhere. |
| `telesphorepo user reset-2fa NAME` | Removes every second factor of the user. |
| `telesphorepo version` | Prints the version. |
| `telesphorepo help [command]` | Shows the help of a command. |

In the container, put `docker exec -it telesphorepo /telesphorepo` before the command. The `user` commands change the database in `TR_DATA_DIR`.

## Environment variables

No variable is required.

| Variable | Default | What it sets |
|---|---|---|
| `TR_DATA_DIR` | `./data`, `/data` in the image | The folder for the database, the files and the master key |
| `TR_LISTEN` | `:8080` | The listen address |
| `TR_MASTER_KEY` | a file in the data folder | The key that encrypts secret settings: 32 bytes, base64 |
| `TR_BOOTSTRAP_ADMIN_USER`, `TR_BOOTSTRAP_ADMIN_PASSWORD` | `admin` and a random password | The first admin. The server reads them only while it has no users |

A change to these variables needs a restart.

## Settings

Change settings in the web UI, on the pages **General**, **Storage**, **Sign-in options** and **Network and proxy** under **Settings**. A change applies at once.

You can also force any setting from the environment. The name is `TR_` plus the key in capitals, with `_` for each `.`. For example, `s3.bucket` becomes `TR_S3_BUCKET`. The web UI then shows the setting as read only.

## HTTP API

The web UI uses a JSON API under `/api/`. The full list of routes is in [SPEC.md](https://github.com/Telesphorepo/Telesphorepo/blob/main/SPEC.md#http-surface) in the source repository.

`GET /healthz` answers `ok` when the server runs. Use it for health checks.
