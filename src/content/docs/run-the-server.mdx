title: Run the server
description: Start Telesphorepo, sign in as the admin and create your first repository.
---

import { Steps, Tabs, TabItem, Aside } from '@astrojs/starlight/components';

You need Docker, Podman, or a Linux, macOS or Windows machine for the binary. The server needs no database server.

<Steps>

1. Start the server.

   <Tabs syncKey="engine">
   <TabItem label="Docker">

   ```sh
   docker run -d --name telesphorepo -p 8080:8080 -v telesphorepo-data:/data ghcr.io/telesphorepo/telesphorepo:latest
   ```

   </TabItem>
   <TabItem label="Podman">

   ```sh
   podman run -d --name telesphorepo -p 8080:8080 -v telesphorepo-data:/data ghcr.io/telesphorepo/telesphorepo:latest
   ```

   </TabItem>
   <TabItem label="Binary">

   Download the archive for your system from [GitHub Releases](https://github.com/Telesphorepo/Telesphorepo/releases). Unpack it, then run:

   ```sh
   ./telesphorepo serve
   ```

   The binary keeps its data in `./data`.

   </TabItem>
   </Tabs>

2. Get the admin password. On the first start, the server prints it once. Copy it from the output.

   <Tabs syncKey="engine">
   <TabItem label="Docker">

   ```sh
   docker logs telesphorepo
   ```

   </TabItem>
   <TabItem label="Podman">

   ```sh
   podman logs telesphorepo
   ```

   </TabItem>
   <TabItem label="Binary">

   The password is in the terminal where you started the server.

   </TabItem>
   </Tabs>

3. Open `http://localhost:8080` in a browser and sign in. The username is `admin`.

4. Set up two-step verification. An admin must do this before any other page opens.

   - Click **Add** on the authenticator app row.
   - Scan the QR code with an authenticator app, then enter the 6-digit code.
   - Create recovery codes and keep them in a safe place.

5. Set the address of the server. Open **Settings**, then **General**. In **Public base URL**, enter the address that your builds use, for example `https://repo.example.com`. Click **Save**.

6. Create a repository. Open the **Repositories** page and click **New repository**.

   - Choose **A repository**.
   - Name it `releases`.
   - Choose the format **Maven**.
   - Under **Who can download**, choose **Public** or **Private**.
   - Click **Create repository**.

7. Add the people who publish.

   - Open **Settings**, then **People**, and click **New account**.
   - Open the repository and click **Settings**. Open the **Access** tab.
   - Click **Add people**, tick the people, and choose **Publish**.

</Steps>

The server runs. Next, [use the repository in a build](/use-a-repository/).

The examples in these docs use `https://repo.example.com` and the repository `releases`. Replace them with your own values.

<Aside type="caution">
Keep the volume `/data`. It holds the database, the files and the key that encrypts your secret settings. Without the volume, you lose everything when the container goes.
</Aside>

<details>
<summary>Choose the first admin yourself</summary>

Set both variables on the first start. The server then prints no password. Type the password at the hidden prompt. `-e TR_BOOTSTRAP_ADMIN_PASSWORD` gives only the name of the variable, so Docker reads the value from your shell and the password stays out of the command line and the shell history.

```sh
read -rsp 'Admin password: ' TR_BOOTSTRAP_ADMIN_PASSWORD; echo
export TR_BOOTSTRAP_ADMIN_PASSWORD
docker run -d --name telesphorepo -p 8080:8080 -v telesphorepo-data:/data \
  -e TR_BOOTSTRAP_ADMIN_USER=alice \
  -e TR_BOOTSTRAP_ADMIN_PASSWORD \
  ghcr.io/telesphorepo/telesphorepo:latest
unset TR_BOOTSTRAP_ADMIN_PASSWORD
```

The server reads the variables only while it has no users. Remove them after the first start.

</details>

<details>
<summary>Lost the admin password</summary>

Set a new password from the command line:

```sh
docker exec -it telesphorepo /telesphorepo user passwd admin
```

</details>

<details>
<summary>Image tags and platforms</summary>

The image supports `linux/amd64` and `linux/arm64`. Each release has the tags `X.Y.Z` and `X.Y`. `latest` is the newest release.

Check a downloaded binary against `SHA256SUMS` on the release page.

</details>
